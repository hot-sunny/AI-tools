1-3. Cluade Code 사용법
  1) 내가 반복하고 있는 일이나 해보고 싶은 것을 Claude Code 에게 입력 문의
     그 후, 구현 요청하기 -> MVP -> 퀄리티 -> 수정 요청(계속 반복할 수록 완성도가 높아짐)
  2) 대표적인 사항
    - 내 하드디스크 용량 정리해줘
    - 내 바탕화면 정리해줘
    - 내 포트폴리오 웹페이지 만들어줘
    - 내 이력 바탕으로 이력서 초안 작성해줘
    ex) 고양이 사진첩 만들기
    prompt) 다운로드 폴더에 있는 roy폴더에 우리 고양이 로이 사진이 있어. 이 사진을 기반으로 귀여운 사진첩을 만들어줘. (웹페이지로 만들어줘)

2. 클로드 권한 설정(세션 권한)
  1) 자동 <--(사용권장)
    - Claude가 권한 결정을 처리한다.
    - Claude가 알아서 일을 처리해 주고 필요한 경우에만 사용자한테 승인을 요청하는 방식
  
  2) 수동
    - 변경하기 전에 항상 확인
    - 거의 대부분의 작업에서 사용자가 검토하고 승인을 해야 진행되는 방식
  
  3) 편집 자동 수락
    - 모든 파일 편집을 자동으로 수락
  
  4) 계획
    - 변경하기 전에 계획 세우기
  
  5) 권한 무시
    - 클로드가 멋대로 내 파일을 수정하거나 삭제할 수 있기 때문에 사용하지 마시고 
      웬만하면 자동으로 해 놓고 사용하시는 게 좋다.


3. 사용예시
  1) "하위 세션" 기능을 활용하면 더욱 효율적으로 작업을 할 수 있다.
  - ex) 업체 3곳으로부터 제안서를 받은 경우
  - prompt)
    업체비교 폴더에 있는 의뢰조건과 업체 제안서 세 개를 비교해줘.
    업체마다 내가 직접 열어 대화할 수 있는 별도의 하위 세션을 만들어 검토를 나눠줘. 모든 하위 세션에 동일한 의뢰조건을 전달해.
    각 세션은 부가세와 필수 옵션을 포함한 총비용, 납기, 결과물, 수정 횟수를 확인해줘. 자료에 없는 조건은 추측하지 말고 '확인 필요'라고 표시해.
    메인 세션에서는 결과를 하나의 비교표로 합치고, 필수 조건을 모두 충족한 업체 중 총비용이 가장 낮은 곳을 추천해줘. 금액 계산식도 보여줘.
  
  - ex) 광고성과 데이터 분석
  - prompt)
    광고성과.csv를 읽고 광고 채널별 성과를 비교해줘.
    채널별 ROAS와 전체 ROAS를 계산하고, 다음 달 예산을 결정하기 전에 추가로 확인해야 할 정보를 정리해줘. 계산식도 보여줘.
    광고비와 매출만으로 실제 이익을 단정하지 마.
    
  2) 사이드 채팅(우측 창에 나타남)
  - 우측 상단 ... > 사이드 채팅 선택
  - 현재 진행하고 있는 추가적인 질문을 할 수 있다.
  - 메인 세션에는 영향을 주지 않는다.
  
  3) 분할 보기
  - 좌측 Claude 카테고리에서 ... 클릭 > 다음에서 열기 > 분할 보기 선택
  - 화면을 반으로 나눠서 동시에 작업을 할 수 있다.
  
  4) 아티팩트
  - 문서, 슬라이드, 디자인, 대시보드 등 실제로 사용할 수 있는 결과물을 만들 수 있다.
  - ex) 사내 AI교육 안내문을 만들어줘.
  - prompt)
    교육안내_메모.txt를 바탕으로 임직원에게 공유할 교육 안내문을 Claude Docs 아티팩트로 만들어줘.
    제목, 교육 소개, 일정표, 신청 방법, 준비물 순서로 구성해줘. 처음 읽는 사람도 참여 대상과 신청 기한을 바로 알 수 있게 정리해줘.
    원문에 없는 참가비, 신청 URL, 녹화 제공 여부는 임의로 추가하지 마.
  
  - 완성된 문서는 특정 부분만 Mouse Drag 해서 이 부분만 수정을 해 달라고 별도로 요청을 할 수 있다.
    prompt)
    이 문단만 두 분장으로 줄여숴. 교육을 듣고 무엇을 할 수 있는지가 먼저 나오게 바꿔줘.
    
  5) 아티팩트 - 슬라이드
  - ex) Claude 2.0을 소개하는 초보자용 PPT를 만들어줘.
  - prompt)
    'Claude 2.0 개념 설명' 자료를 바탕으로, AI를 처음 쓰는 직장인도 쉽게 이해할 수 있는 한국어 슬라이드 12장을 만들어줘.
    중요한 개념과 실제 업무 활용법 위주로 구성하고, 어려운 용어는 쉬운 비유로 설명해줘.
    16:9 비율에 크림색 배경, 짙은 글씨, 오렌지 포인트로 깔끔하고 세련되게 디자인해줘.
    한 장에 핵심 메시지 하나만 담고, 글을 빽빽하게 넣기보다 비교표,도식,예시로 시각화해줘.
    내용에 맞춰 레이아웃을 다양하게 구성하고, 글씨는 크게 해줘.
    요금이나 모델 버전처럼 바뀔 수 있는 정보는 확인된 내용만 넣고, 완성 후 글자 겹침과 잘림을 점검해줘.
    결과는 직접 수정하고 발표할 수 있는 Claude Slides로 만들어줘.
    
  - ex) PKCS#11 소개하는 초보자용 PPT를 만들어줘.
  - prompt)
    PKCS#11 를 처음 쓰는 개발자도 쉽게 이해할 수 있는 한국어 슬라이드 12장을 만들어줘.
    PKCS#11 중요한 개념과 PQC(Post-Quantum Cryptography) 실제 파이썬 코드 개발 활용법 위주로 구성하고, 어려운 용어는 쉬운 비유로 설명해줘.
    16:9 비율에 크림색 배경, 짙은 글씨, 오렌지 포인트로 깔끔하고 세련되게 디자인해줘.
    한 장에 핵심 메시지 하나만 담고, 글을 빽빽하게 넣기보다 비교표,도식,예시로 시각화해줘.
    내용에 맞춰 레이아웃을 다양하게 구성하고, 글씨는 크게 해줘.
    파이썬 샘플 코드나 모델 버전처럼 바뀔 수 있는 정보는 확인된 내용만 넣고, 완성 후 글자 겹침과 잘림을 점검해줘.
    결과는 직접 수정하고 발표할 수 있는 Claude Slides로 만들어줘.

  6) 아티팩트 - 디자인
  - ex) Claude 2.0 인스타그램 카드뉴스를 만들어줘.
  - prompt)
    Claude 2.0 개념 설명 파일을 가지고, AI 초보자와 직장인들의 흥미를 이끌 수 있는 인스타그램용 카드뉴스를 디자인해줘.
    깔끔하고 세련되게, 줄글 보다는 핵심 용어, 시각화와 도식화 위주로.
  
  7) Mods
  - 내가 직접 원하는 기능을 만들어서 이 클로드에 추가할 수 있는 기능
    즉, 클로드를 내 입맛대로 커스터마이징 할 수 있는 기능이다.
  - prompt)
    클로드 코드 화면 옆에 검토 체크리스트 모드를 만들어줘.
    '숫자 확인', '원본 자료 확인', '공개할 정보 확인'을 내가 직접 체크할 수 있게 하고, 완료 개수와 초기화 버튼도 넣어줘.
    -> How does this work? Turn them on (체크): 우측 사이드에 화면 생성됨
  
  8) 팻 Mod
  - ex) 세션의 작업이 끝나면 알려주는 귀여운 강아지 펫 Mod를 한 번 만들어 보자
  - prompt)
    클로드 코드 화면 옆에 귀여운 강아지 팻 모드를 만들어줘.
    작업 중에는 노트북을 두드리고, 내 확인이 필요하면 앞발을 들고, 응답이 끝나면 꼬리를 흔들어 "끝났어!"라고 알려줘.
    실제 세션 상태에 맞춰 자동으로 반응하고, 내가 작업을 중단했을 때는 완료 알림을 보내지 않게 해줘.
    작고 귀여운 픽셀 아트 스타일로 만들고, 알림은 켜고 끌 수 있게 해줘.

  9) 명령어 기능
   - /명령어를 사용자가 직접 만들어서 사용할 수 있다.
   /compact  - 해당 세션의 이전 대화 내용과 맥락을 압축해서 요약하고 남은 컨텍스트 공간을 확보해 주는 기능
             - 클로드와 대화를 하다가 틈틈이 이 compact 를 사용해 주면 토큰을 아끼면서 사용할 수 있다.
             
   /output-style  - 결과물을 어떤 식으로 출력해 줄지 답변 스타일을 바꿀 수 있는 기능
                    "전문적이고 상세한 답변"이 필요한 경우도 있고, 또는 "핵심만 빠르고 간결하게 정리"해 줬으면 하는 기능
                  - 스타일 선택: Proactive, Concise, Explanatory, Learning(학습용) 중 선택        
   
   
   /goal  - 작업을 수행해 줄 때 "완료할 수 있는 조건 제시"해 주는 기능
          - 사용자가 제시한 조건을 만족시키지 못하면 클로드가 이 목표를 달성할 때까지 계속해서 작업을 해 주게 됨
            최종적으로 모든 조건을 충족한 뒤에야 작업을 끝내 준다.
            클로드가 스스로 결과를 확인하고 필요한 부분을 고쳐가기 때문에 내가 일일이 후속 프롬프트를 입력하고 계속해서 간섭할 필요가 없어진다.
          - 주의점: 목표를 명확하게 제시해 주어야 한다. 그렇지 않으면 클로드가 무한으로 작동하는 것을 방지할 수 있다.

* AI바이브코딩으로 기능 추가시 중요한 점
  1) 이 기능 추가는 무엇으로부터 시작한 걸까요? 바로 "사람"으로부터 시작한 것이다. 즉, "사람"이 상상을 했기 때문이다.
     "이렇게 누루면 애니메이션이 있으면 좋겠다"라고 상상을 했기 때문에 시작이 된 것이다.
  2) 그리고 그 이후에 이걸 어떻게 하면 구현을 할 수 있을까라는 것도 "사람"의 머릿속에 대략적으로 있었던 거다.
     또 그것을 AI에게 설명을 해줄 수가 있었던 것이다.
  
  결국에는 제일 처음에 "상상"을 하고 "디자인"을 하고 시키는 일을 하는 것은 "사람"이 하는 것이다.
  그래서 "상상력"이 중요한 시기가 된 것 같다.
  
  그냥 무턱대고 어 나 이거 마음에 안들어 좀 더 이쁘게 해줘 라고 했으면 AI가 잘 했을까. 아니다 정말 어디로 갔을지 모르고 진짜 중구난방으로 이상해졌을 수도 있다.
  
  AI가 사람을 도와주는 존재이고, 또 사람은 도구로 잘 활용할 수 있는 것인데
  그것을 잘 활용하려면 
  
  첫째, 정말 우리가 "구체적으로 상상"을 할 수 있으면 너무 좋고, 
  두번째, 그 상상한 것을 코드로 했을 때 내가 어떻게 하면 좋을지 그 "알고리즘"과 "디자인" 까지도 머릿속에 있으면 좋다.
  
  그래서 바이브코딩을 하기 위해서는 "코딩의 기초", 그리고 "알고리즘의 기초" 같은 것도 다 있으면 좋은 것 같다.
  사람이 상상을 할 수 있다면, 그것을 만들 수 있는 도구가 바로 바이브코딩이다.
  
  
* AI바이브코딩 과정 실습
  - 예제: 논문읽기앱(페이퍼AI)에서 하이라이딩 기능이 있는데, 문장 중 일부는 한 번 클릭하면 하이라이트가 바로 적용이 된다.
          그런데 이 기능을 조금 더 이쁘게 바꾸고 싶다.
          하이라이트가 빠르게 정말 펜으로 긋는 것처럼 생기면 어떨가? 하고 생각을 한다.
          그래서 그것을 한번 프롬프팅을 짜서 클로드코드한테 한번 물어보도록 하겠다.
          
          -->[중요] 바이브코딩을 할 때는 "프롬프팅"이 정말 중요하기 때문에, 
          --        신중하게, 최대한 자세하게 기술해서 짜야한다.
  - 프롬프트:
    1. 내 논문 읽기 앱은 하이라이트 기능이 있다. 한 문장을 클릭하면 한글과 그에 대응되는 영어 문장이 하이라이트 된다.
    2. 한글과 영어 문장들은 org-x-y, trans-x-y, 이런 식으로 paragraph ID와 sentence ID로 구성된 span ID가 붙어 있고 이것을 기반으로 동작한다.
       하이라이트가 생성되면 store의 annotations에 저장되는 방식이다.
       이 기능을 일단 리뷰하고 파악해주세요.
    
    -->[중요] 바이브코딩은 차근차근 단계별로 하는 것이 좋기 때문에
    --        일단 내가 implement(구현)한 기능이 어떤 기능인지를 사람이 문장으로 설명을 해준다.
    --        그리고 이것을 일단 AI에게 파악해달라고 하도록 한다.
    --        바로 시키는 것 보다는 사람하고 얘기할 때도 일단 서로 "배경 지식"을 맞추는 것처럼 얘기는 시작한다. 그것처럼 AI한테도 그렇게 하는 게 좋다.
    -->[중요] 사람과 AI 간 서로의 "배경 지식" 맞추기. (AI에게 현재 상황을 최대한 자세하게 설명을 해준다)
    
    3. AI가 기존 코드를 정확하게 파악하여 정리를 해서 그 결과물을 제시한다.
       그러면 AI와 사람이 배경 지식이 똑같이 맞춰지게 된다.
       그 다음 조금 더 "구체적인 명령"을 내려본다.
       
    -->[중요][구체적인 명령] 프롬프트 추가하기
    --        "새 기능을 어떻게 하면 구현할 수 있을까?" 일단 사람 자신의 "아이디어"를 구체적으로 짜서 AI에게 제안을 먼저 한다.
    4. "스팬으로 되어있으니까 그 속에 엘리멘트들을 다 작은 스팬으로 잘라서 시간에 따라서 하이라이트를 쭉하고 보여주는 게 어떨까" 하고
       AI한테 한번 제안을 해보도록 한다.
       그때 제안한 아이디어에 대해 "이 계획이 적절한지", 아니면 "더 좋은 방법이 있는지" 알려달라고도 말한다.
       왜냐하면 때로는 제가 그냥 복잡하게 생각한는 것보다 훨씬 더 씸플하게 AI가 솔루션을 가지고 있는 때도 있다.
       그래서 겸손하게 이렇게 묻는게 더 좋은 것 같다.
       
    5. 내가 하고 싶은 것은 클릭을 하였을 때에 바로 하이라이트가 적용디는 것이 아니라 마치 하이라이트 팬으로 긋듯이, 처음 글자부터 마지막 글자까지 색이 빠르게 칠해지는 효과를 내는 것이다.
       이를 위해서 내가 구상을 해 보았다.
       다음과 같은 것이 어떨까?
       
       결국 span으로 되어 있으므로, span속에 글자(또는 내부 태그)가 30자가 있다고 하자. 
       그러면 span 속의 각 글자 또는 tag들을 org-x-y-t로 감싸는 것이다. 그리고 t가 작은 숫자에서 큰 숫자에 이르기까지 하이라이트를 빠르게 붙이는 것이다.
       1초 동안 하면 되겠다. linear하게 올라가지 않고 ease in ease out으로 해 주면 좋겠다.
       그리고 동일한 시간동안 영어 쪽 또한 같이 올라가도록 해야 할 것이다.
       
       이 계획이 적절한디 아니면 더 좋은 방법이 있는지 알려주세요.
       만일에 한다면, 복잡하지 않게 하나의 composable로 모든 기능을 묶고 싶다.
         
    6. AI가 더 효율적인 방법을 제시하는 경우 해당 부분 검토하여 답변을 준다.
       AI 제안: CSS 기반 그라데이션 애니메이션
                각 글자를 span으로 감싸는 대신, CSS linear-gratient 와 animation을 활용하는 방법이 있습니다.
       --> 네 제안이 더 좋은 것 같다. 구현해 주세요.
       --> 결과물을 체크하고 테스트를 진행해 본다. 그리고 해당 결과물에 이상이 있으면 AI에게 불만을 토로한다.
    
    7. 누르면 그냥 커다란 네모가 왼쪽에서 오른쪽으로 날아오는 것처럼 구현되었다. 
       span의 특성상 여러 줄에 나뉘어 있을 경우가 있는데 이 경우 newline을 고려하면서 차근차근 칠해져야 하지 않을까?
       --> 약 10분간 동안 AI와 여러번의 자잘한 조정 이후 .... 결과물을 완성
       --> AI가 새롭게 추가한 기능들은 이 뷰 컴포저블에 다 넣어달라고 했다. 왜냐하면, 딴 데 다 섞여있으면 나중에 디버깅하기가 너무 힘들기 때문이다.
       --  항상 한가지 일을 끝내면 git commit을 하는 게 좋다.
       > commit 해주세요

* AI바이브코딩에서의 중요한 점
